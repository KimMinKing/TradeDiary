# 거래소 API 키 암호문 전환

거래소 API 키·시크릿·패스프레이즈의 새 암호문은 `v2:` 접두사와 Base64로 인코딩한 nonce·암호문·인증 태그로 저장합니다. AES-GCM은 저장할 때마다 새로운 12바이트 nonce와 128비트 인증 태그를 사용합니다.

기존 접두사 없는 AES-CBC 암호문은 계속 읽을 수 있습니다. 애플리케이션 시작 시 `ExchangeKeyEncryptionMigrator`가 기존 값을 복호화해 새 형식으로 다시 저장합니다. 세 필드 중 하나라도 복호화할 수 없는 레코드는 건드리지 않고 ID만 로그에 남깁니다. 연결 목록은 해당 거래소를 숨기지 않고 재연결 필요 상태로 표시합니다.

재연결은 기존 `exchange_keys` 행의 인증 정보를 갱신하고 비활성 키를 다시 활성화합니다. 고유 제약이 있는 행을 삭제·재삽입하지 않으며, 연결된 동기화 상태를 새 가져오기 작업으로 초기화합니다.

운영 적용 전에는 DB 백업을 만들고 **기존 `AES_SECRET` 값을 그대로 유지**해야 합니다. 키가 바뀌면 기존 암호문을 복호화할 수 없습니다. 전환 후 암호문은 이전 버전의 백엔드에서 읽을 수 없으므로, 배포를 되돌릴 때도 이 버전 이상의 복호화 코드를 유지해야 합니다. `V116__ExpandExchangeCredentialCiphertext.sql`은 암호문 길이를 위해 세 컬럼을 2048자로 확장합니다.

검증은 `./gradlew test migrationTest`로 수행합니다. 테스트는 기존 CBC 암호문 복호화, GCM 암호문의 nonce 차이와 변조 거부, 임시 PostgreSQL에서의 전환·재실행을 확인합니다.
