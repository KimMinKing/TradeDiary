# 알림·프로필·거래 계획 보안 개선

## 알림

- 클라이언트가 임의 사용자 ID로 알림을 만들 수 있던 WebSocket 테스트 메시지 경로와 수동 세션 등록 API를 제거했다.
- 운영 REST API에 남아 있던 테스트 알림 생성 경로를 제거했다.
- 실시간 알림은 JWT WebSocket Principal과 서버 내부 이벤트만 사용한다.
- `V104__NotificationIdempotency.sql`에서 `(user_id, related_id)`를 고유하게 만들어 같은 이벤트의 알림이 반복 저장되지 않도록 했다.
- 마이그레이션 시 중복 이벤트는 가장 최신 알림을 보존한다.
- 페이지 요청 크기는 최대 100개로 제한해 과도한 조회로 인한 응답 지연을 방지한다.

## 프로필 이미지

- 아바타에도 일기 사진과 동일한 서버 측 MIME, base64, 파일 시그니처 및 1.5MB 검증을 적용한다.
- 브라우저에서는 JPEG, PNG, WebP만 선택할 수 있고 원본 파일을 5MB로 제한한 뒤 80x80 JPEG로 변환한다.

## 거래 계획

- 생성과 수정 요청에 Bean Validation을 적용했다.
- 내용은 필수이며 최대 5,000자, 종목은 최대 40자다.
- 방향은 `LONG`, `SHORT`, `BUY`, `SELL`만 허용한다.
- 기존 수정·삭제·완료 처리의 사용자 소유권 조건은 유지된다.

## 검증

- 백엔드 전체 테스트
- 프런트엔드 프로덕션 빌드
- 빈 PostgreSQL에서 V100~V104 전체 Flyway 실행
- 로컬 DB V104 적용 후 중복 이벤트 0건 및 고유 인덱스 생성 확인
